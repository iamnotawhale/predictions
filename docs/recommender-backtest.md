# Рекомендатор: что показал бэктест (3 сезона АПЛ)

Скрипт: `tools/recommender-backtest/backtest.py` (данные: `E0.csv` с football-data.co.uk за 2022/23–2024/25,
1140 матчей, закрывающие коэффициенты Pinnacle + линия тотала 2.5). Запуск описан в начале скрипта.

## Главное

1. **Рынок откалиброван.** Средние вероятности (дом/ничья/гости) 0.450 / 0.230 / 0.321 против фактических
   0.451 / 0.230 / 0.319; логарифмическая потеря 0.942 (равные шансы: 1.099). Это сильный источник вероятностей.
2. **Независимый Пуассон, подогнанный под рынок (1X2 + тотал 2.5), достаточно хорошо описывает счета.**
   Поправки на ничьи (Dixon–Coles, инфляция диагонали) улучшают логарифмическую потерю счёта только в
   четвёртом знаке (2.9866 → 2.9861), поэтому не нужны.
3. **Правило выбора счёта важнее, чем кажется.** По правилам игры (EPL 4/2/1/−1) выбор счёта с
   максимальными *ожидаемыми очками* даёт +0.575 очка за матч против +0.436 у «самого вероятного счёта»
   на тех же вероятностях: **+0.139 [95% ДИ +0.020; +0.258]**, во всех трёх сезонах лучше
   (0.56/0.61/0.56 против 0.37/0.55/0.38). Ожидание модели (0.564) совпало с реальностью (0.575).
4. **Выбор по ожидаемым очкам устойчив к «сжатию» вероятностей к среднему, мода — нет.** Если вероятности
   рынка сжать вдвое: EV-выбор 0.575 (не изменился), модальный 0.151. Модальный выбор при слабо
   контрастных вероятностях тянется к 1:1 (48% всех выборов), что в среднем убыточно (−0.10 за матч).
5. Без информации о матче (одно и то же для всех) EV-выбор даёт 0.28; значит, рыночная информация
   добавляет ≈ +0.29 очка за матч.
6. Те же выводы по правилам «бонус» (5/3/2/0) и «кубок» (2/1/0): EV-выбор лучше моды.

## Чего тест не показывает

- Нет истории статистики FootyStats/SoccerStats, поэтому **вклад блока статистики команд не проверен**
  (только рынок + правило выбора). На 38 матчах из прод-БД его не отличить от шума (нужно ≈ 700+ матчей).
- Приложение использует коэффициенты ESPN, а не закрытие Pinnacle; они шумнее.
- Прошлая оценка «λ модели завышены / двойной учёт домашнего преимущества» **не подтвердилась**: средняя
  λ модели (1.65 : 1.40) близка к долгосрочным 1.65 : 1.37 голов за матч; на 38 матчах расхождение шум.

## Выборка из прод-БД (38 матчей) — почему не годится для настройки

Ничьих 39.5% (при ~23% в долгосроке, p≈0.03), побед хозяев 26% (при ~45%, p≈0.02). На ней рынок и модель
одинаково хуже «равных шансов». Разница между вариантами в очках лежит внутри доверительных интервалов.

## Проверка боевого кода (Java) на тех же 1140 матчах

`RecommenderBacktestTest` (запуск: `BACKTEST_DIR=<папка с E0*.csv> mvn -Dtest=RecommenderBacktestTest test`) гонит
реальный `PoissonScoreModel` с нейтральной статистикой команд (проверяется рыночное ядро):

| показатель | значение |
|---|---|
| очки за матч, рекомендуемый счёт (макс. ожидаемых очков) | **0.55** |
| очки за матч, самый вероятный счёт (как было) | 0.33–0.35 |
| логарифмическая потеря 1X2 | 0.9427 (рынок: 0.9422) |
| средние P(дом/ничья/гости) | 0.446 / 0.233 / 0.321 (факт 0.451 / 0.230 / 0.319) |

Вес статистики в форме счёта (0 / 0.15 / 0.3) на результат не влияет (0.554 / 0.552 / 0.556), способ снятия
маржи (пропорциональный vs степенной: +0.006, ДИ −0.011…+0.024) и цель по тоталу (2.89 vs 3.0: +0.025,
ДИ −0.007…+0.058) статистически неотличимы от нуля — поэтому не подгонялись.

## История прошлых сезонов и H2H сверх рынка

На 760 матчах (сезоны 23/24 и 24/25) рейтинг прошлого сезона не добавляет информации сверх коэффициентов
(β = +0.02, p = 0.67); единственный намёк — первые 8 игр сезона (β = +0.32, p = 0.013 при ~10 проверенных
гипотезах, n = 160). H2H из таблицы `h2h` сверх рынка не помогает (β = −0.08, p = 0.37; при 6+ встречах β = 0.00).
Без рынка рейтинг прошлого сезона заметно лучше статистики текущего сезона в первые 8 игр
(логарифмическая потеря 0.925 против 1.003) и вместе с ней даёт 0.910 (рынок 0.902).
